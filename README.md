# 汉衡 · HanGauge

中文基础文本能力评测。不考知识储备，不考数学和逻辑难题，不考写代码和 Agent 任务，只考模型能不能把一段中文读懂、理清、概括和改写。

360 道题 = 20 项能力 × 6 个领域 × 3 档难度。每题只取模型的第一次原始回答，对照固定参考答案评分；题目、材料、回答、分数和评分理由全部公开。

**[公开浏览与对比](https://leafiy.github.io/hangauge/)** · [源码](https://github.com/leafiy/hangauge)

公共页面不需要注册或 API Key，不调用模型，也不提供修改、删除或启动评测的接口。需要评测自己的模型时，在本地运行应用。

## 为什么做这个

现在的模型榜单大多在比知识、推理、编程和 Agent。但模型接进实际业务后，做得最多的是基础文本工作：判断一段话的情感和立场，抽取实体、关系和事件，按规则核对条件，解读数字，脱敏，摘要，改写，翻译。这些能力在主流榜单里很少被单独拿出来看，模型之间的差距却不小（见[内置结果](#内置结果)）。汉衡只测这一块。

## 特色

- **考理解，不考背诵。** 每道题都自带材料，并要求只依据材料作答，不得搜索或补充常识。答案在给定的文字里，不在模型的记忆里。
- **题目来自日常文本工作。** 材料取自或仿照六个领域的真实文本：法规和部门规章、保险条款、银行协议、电商与生活服务平台规则、健康科普、论文摘要、官方技术文档。95 题直接使用 37 个公开来源的原文短摘录，其余 265 题是按考点构造的短文本。
- **该答“没有”时要答“没有”。** 每道题都允许四种结论：正常作答、材料中没有目标内容、信息不足、存在歧义。参考答案里有 80 题不是正常作答：52 题没有目标内容，18 题信息不足，10 题有歧义。在这些题上硬答或补造内容，就与参考答案不一致。
- **能力 × 领域 × 难度全交叉。** 20 × 6 × 3 的每一格恰好 1 题，所以每项能力都有 18 题，覆盖全部领域和难度；每个领域 60 题，覆盖全部能力。难度分基础、边界、复合三档：边界题侧重信息缺失、歧义和易混淆的临界情形（80 道非正常作答题里有 63 道在这一档），复合题叠加多个条件、限制或多段材料。题号后缀 B、E、C 依次对应这三档。
- **只算第一次回答。** 每题单独提问，不共享会话，不修复输出，不自动重试。
- **每一分都能查。** 页面上可以展开任一能力的全部 18 题，查看题目、材料、参考回答、模型原始回答、分数和评分理由。未回答和未评分保持缺失，不填成零分。
- **本地就能测自己的模型。** 只用 Python 标准库，支持任何 OpenAI Chat Completions 兼容接口，包括本地部署的开源模型。

## 与其他评测的区别

| 评测类型 | 主要考什么 | 汉衡 |
|---|---|---|
| 知识考试型，如 C-Eval、CMMLU | 学科和专业知识，以选择题为主 | 不考知识储备，答案只在给定材料里 |
| 推理、编程与 Agent 型 | 解难题、写代码、调用工具完成任务 | 不涉及，只考文本的读和写 |
| 传统中文理解基准，如 CLUE | 为预训练判别式模型设计，以分类、句对匹配和阅读理解为主 | 面向生成式模型：同一套作答要求下既有判断和抽取，也有摘要、改写和翻译，每题都要先判断能不能答 |

这些评测各有侧重，互不替代。汉衡只补基础文本能力这一块，分数高低不代表模型在知识、推理或编程上的水平。

## 内置结果

| 记录 | 已回答 / 已评分 | 综合分 / 100 | 性质 |
|---|---:|---:|---|
| DeepSeek Flash | 360 / 360 | 81.75 | 已完成实测，只读 |
| Qwen3.8 27B FP8，禁止思考 | 360 / 360 | 71.14 | 已完成实测，只读 |
| GPT-6.1 SOL xhigh | 360 / 360 | 100 | 已确认参考，不是独立评测成绩 |

三份记录均来自已经完成的原始运行。本项目没有为了发布而重新作答、重打分或修改答案。

同一个模型各项能力的分数相差很大，只看综合分看不出来：

- DeepSeek Flash 最高的一项是情感与情绪分析（100），最低的一项是立场与观点归属（33.33）。后者是直接判断题，整题结论与参考完全一致才得分。
- 两个模型差距最大的一项是忠实改写与文本整理：87.50 对 40.89。
- 综合分低约 10.6 分的 Qwen3.8 27B，在质性编码与框架分析、论证结构分析、新词发现三项上略高。

页面支持对比综合分、20 项能力和 6 个领域；展开任务可查看全部 18 题的题目、材料、参考回答、模型回答、分数及理由。未回答和未评分保持缺失，不填成零分。

## 本地启动

需要 Python 3.10+；仅使用标准库，无需安装依赖或构建前端。

```bash
git clone https://github.com/leafiy/hangauge.git
cd hangauge
bash start.sh
```

打开 <http://127.0.0.1:8960>。也可直接运行 `python3 server.py`。

本地页面分别配置两组 OpenAI Chat Completions 兼容接口：

- **被测模型**：Base URL、模型 ID、API Key、temperature、max_tokens、思考设置；用于生成首次回答。
- **评分模型**：独立的 Base URL、模型 ID、API Key 和生成参数；用于理解类题目的内容评分。

公开设置可以保存；两组 API Key 都不会写入设置、结果文件、浏览器存储或日志，使用时重新填写。无鉴权接口可留空。不要把密钥放进 URL、模型名、名称或备注。

支持全部 360 题、每任务首题 20 题、连通性首题 1 题。每题使用独立消息，只保存第一次返回，不共享会话，不修复输出，不自动重试。模型调用可能产生费用。全部目标题作答完成后自动评分；已有未评分回答可单独评分，不重新作答。

作答阶段可请求停止，等待当前请求结束后保留已完成回答。错误和中断会如实保存；不会把缺失答案伪装成错误答案或完整成绩。更换评分配置不能将不同评分模型的分数悄悄混入同一条部分评分记录。

新运行默认存入 `results/`，该目录被 Git 忽略。可指定保存目录和端口：

```bash
bash start.sh --port 8962 --data-dir /your/local/results
```

## 公开部署

### 无后端静态页面

仓库的 `docs/` 是从校验通过的三份内置记录生成的静态网站，适用于 GitHub Pages 的 `main /docs` 发布源。静态页面不包含密钥，不连接推理服务，也不能修改记录。

重新生成：

```bash
python3 build_static.py
```

也可用 `--output /path/to/site` 指定目录。生成过程只读取内置记录，不导出本地 `results/`，不调用任何模型。部署到域名子目录时无需修改资源路径。

### 只读 HTTP 服务

```bash
bash start.sh --read-only --host 0.0.0.0
```

只读模式在服务器端拒绝所有修改、删除、设置保存、评分和测试请求，不只是隐藏按钮。可写模式仅允许监听回环地址；不要将本地可写服务经反向代理或端口映射开放给不可信访问者。

内置结果原本就公开；如果用只读服务展示自有 `--data-dir`，该目录里的普通评测也会公开，请先检查回答及运行信息。应用不是多用户托管推理服务，没有账号或管理员认证。

## 评分口径

- **固定参考**：GPT-6.1 SOL xhigh 的已确认 360 条首次回答，不是独立人工金标。参考显示的 100 分只是对照标尺，不是对该模型能力的独立证明。
- **5 类直接判断题**：情感与情绪、立场与观点归属、语义推断、多标签分类、政策条件应用。结论一致得 100 分，不一致或没有可核对结论得 0 分；不因字段顺序、证据路径、局部编号或排版不同扣分。
- **15 类理解题**：将公开题目、材料、固定参考和候选回答交给配置的评分模型，返回 0–100 分及理由。接受等义表达；无效评分明确报错，不填默认分数。
- **任务分**：该任务已评分题目的平均分，始终同时展示覆盖题数。
- **综合分**：20 项能力等权平均，每项占 5%；仅在全部 360 题评分完成后显示。
- **领域分**：该领域 60 题的平均分；仅在该领域全部评分完成后显示。

汇总使用未四舍五入的逐项分数，最后展示到两位小数。内置 DeepSeek 与 FP8 的理解题历史评分模型均记录为 `qwen3.8:27b`；本地新运行由用户配置评分模型，并保存配置来源。修改设置不会重算已有内置成绩。

## 局限

- 分数是**相对于固定参考、在本题集上的汇总结果，不是准确率或通用模型排名**。
- 固定参考是模型的已确认回答，不是独立人工金标。
- 材料以短文本为主：每题材料合计字符数的中位数是 38，最长 271，50 题含多段材料。考的是细读，不代表长文档、全部子任务或真实业务分布。
- 题库与参考公开，不具备防训练污染保证。
- 不同评分模型、提示词、生成参数、思考模式和输出通道会影响可比性。内置两份实测结果的理解题由 `qwen3.8:27b` 评分，与被测的 Qwen3.8 27B 同族，可能存在偏向。
- GPT-6.1 SOL 使用独立原生助手会话，其中有结构化提交通道；其他内置结果使用自由文本 Chat Completions。因此 JSON 可解析率不适合直接横向比较，本项目不将其作为能力分。

## 内置记录保护与来源

`bundled/manifest.json` 固定三条记录的 ID、公开文件 SHA-256、原始源文件 SHA-256，以及原始回答和评分的内容摘要。启动和静态导出均校验内置文件及题集；文件缺失、变更或不完整时明确失败，不自动替换参考。

| 记录 | ID |
|---|---|
| DeepSeek | `2df958eb-e16e-44c4-b537-73b0ece04b29` |
| FP8 | `cbc35b0a-998e-49aa-8407-54618d1efcb6` |
| GPT-6.1 SOL | `ad52a518-e012-46b5-a2df-d6b51650649c` |

三条记录均不能通过应用修改、删除、停止、追加回答或重新评分；即使自定义保存目录中存在同 ID 文件，也不能替换内置内容。只有 GPT 记录属于评分参考，其余两条仍展示真实实测分，不能因为受保护就显示成 100 分。

公开导出仅移除了 FP8 的私有接口地址、GPT 原运行的本机会话目录和题库清单中的本地路径。**原始回答文本、逐题评分及理由、题目内容没有改写。** 脱敏后的公开文件与原始文件字节摘要可能不同，两者均记入清单。旧历史评分字段保留为来源证据，当前显示以 `evaluations` 和派生 `assessment` 为准，不使用旧草标分数覆盖现有评分。

应用层只读保护和 SHA-256 校验不等于操作系统防删、数字签名或外部备份；仓库所有者、文件系统管理员仍有修改文件和清单的权限。

## 项目结构

```text
server.py          本地 API、只读保护与结果持久化
evaluator.py       OpenAI 兼容模型请求
grading.py         直接判断、模型评分与汇总
index.html         公共浏览和本地评测页面
app.js             分数对比、逐题明细、设置与运行状态
dataset.json       冻结题目、草标、来源与签名
bundled/           三份只读记录及完整性清单
results/           用户自己的结果与公开设置，不进入 Git
build_static.py    从内置记录生成公开静态页面
docs/              GitHub Pages 发布文件
```

没有内网网关、专用 GPU、数据库、消息队列或原项目 Python 包的依赖。
